Design & Justification

Pipeline

Document → extraction rules → Knowledge Base (triples + frames + part-of hierarchy) → grounding of the question against KB vocabulary → production rules R1–R9 (search, inference) → answer + explanation trace → evaluation.

Why symbolic AI, and why not NLP/RAG

The brief forbids NLP and RAG, so the system uses no tokenizer pipeline, stemming, POS tagging, embeddings, TF-IDF, vector search or language models. Only regular-expression pattern rules (deterministic extraction) and dictionary look-up against labels already in the KB are used. A tiny stop-list is used solely to detect unknown words so the system can abstain. A rule-based knowledge system is chosen because it is deterministic, explainable (every answer carries its rule and source line) and directly demonstrates knowledge representation, search and reasoning (CO-1 to CO-4).

Knowledge representation

  • Triples (subject, predicate, value, unit, line) – each is one fact.
  • Frames – all facts of one subject form its frame (slots = predicates).
  • Semantic network – part of links (heading hierarchy, table rows) and values that name other entities form graph edges.

Extraction rules

  • E1 headings → entities + part of; E2 Key: value → slot; E3 bullets under Key: → multi-valued slot; E4 table rows → frames (header = slot, unit from “(km)”); E5 “X is/are …”, “X has …” → is / has facts.

Reasoning rules

  • R1 compare frames · R2 superlative (arg-max/min search) · R3 constraint filtering (generate & test) · R4 enumeration/counting · R5 reserved · R6 yes/no verification with closed-world assumption · R7 definition · R8 attribute look-up with BFS graph search and property inheritance (depth ≤ 2) · R9 fallback overlap ranking or abstention.

Limitations

Works best on structured documents; questions must use words that exist in the KB (no paraphrase understanding); free prose beyond the E5 patterns is not captured. These are deliberate trade-offs of the symbolic, no-NLP design.
